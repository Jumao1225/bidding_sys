# 2026-08-17 更新日志

## 标书生成与表格回填（BidFiller）2D 矩阵写盘与技术偏离表修复

### 1. 问题背景
在标书回填 Word 过程中，【技术要求响应及偏离表】等长章节 Worker 成功检索并生成了多行技术响应条款（通过 `officecli_fill_table_rows` 提交 2D 矩阵），但最终生成的 Word 文件中偏离表仍为空白。

### 2. 根本原因定位
1. **字符串断言阻断**：主控 Agent 的 `fill_docx_proposals_in_dom` 中，原逻辑使用严苛的 `p_val.startswith("[[")` 进行表格提案过滤；
2. **格式化换行拦截**：大模型或工具序列化输出带有换行符和缩进的 JSON（如 `"[\n  [\"光伏组件...\"`），导致 `startswith("[[")` 返回 `False`；
3. **提案静默丢弃**：由于被误判为非表格提案，且后续单槽位处理又因 `[` 开头跳过，导致偏离表等 2D 矩阵提案在写盘阶段被 100% 静默忽略。

### 3. 改动明细
1. **`backend/app/agents/bid_filler_agent.py`**：
   - 重构 `fill_docx_proposals_in_dom` 对 `table_rows` 2D 矩阵的识别与解析逻辑，取消脆弱的字符串前缀匹配；
   - 采用稳健的 JSON 解析与二维列表校验，完美兼容带换行、缩进及对象化 2D 矩阵的任意格式；
   - 优化表头列与序号自动对齐机制，未包含序号列时自动在第 1 列补齐 1..N 递增序号；
   - 增加表格无法解析时的清晰告警日志。
2. **`backend/app/agents/bid_filler_workers.py`**：
   - 升级 `_parse_proposals` 中对 `table_rows` 的类型推断，支持反序列化检验与 `/body/tbl[N]` 物理路径判定。
3. **`backend/tests/unit/test_bid_filler_worker.py`**：
   - 新增 `test_fill_docx_proposals_in_dom_formatted_json_matrix_deviation_table_should_succeed` 单元测试，验证格式化换行 JSON 偏离表提案 100% 成功刷盘到 Word。

### 4. 验证结果
- 单元测试覆盖格式化 JSON 偏离表写入、表头对齐、序号自动注入、表尾汇总行保护等场景，测试全部通过（`ALL TABLE TESTS PASSED 100%`）。

## 偏离表伪语法污染拦截与 Tool-First 提案保护加固

### 1. 问题背景
图片反馈显示：技术偏离表第 1 行第 3 列被填入了 `"其他辅材技术要求 + 服务承诺 + '无' + '完全响应招标文件要求，无偏离。'"` 概括文本，第 2 列及后续行全空。

### 2. 根本原因定位
1. **提案覆盖顺序颠倒**：Worker 提案双路融合时，文本提取提案后遍历，覆写了工具调用捕获的权威 2D 矩阵；
2. **大模型偷懒伪语法误提取**：大模型在终端总结里输出了带 `+` 拼接的概括性描述，被 `_parse_proposals` 当作文本提案错误提取并写入单元格。

### 3. 改动明细
1. **`backend/app/agents/bid_filler_workers.py`**：
   - 确立 **Tool-First 原则**：工具捕获的结构化提案（2D 矩阵）具有最高权威，并在有整表提案时自动清理文本误提取的行级伪提案；
   - 彻底废除特定业务关键词黑名单，采用**纯通用抽象语法规则**：
     * 规则 1：通用运算符表达式校验，过滤大模型伪拼接字符串（`\S\s*\+\s*\S`）；
     * 规则 2：通用元数据状态词过滤（`—`, `同上`, `略`, 状态标记等）；
     * 规则 3：表格路径与类型严格归一化：整表路径必须为合法 2D 矩阵，行级路径（未指定单元格 `tc`）严禁作为单文本写入，防止错列。
   - 强化通用 Prompt 指引，严禁大模型输出伪语法。
2. **`backend/app/agents/bid_filler_agent.py`**：
   - 彻底移除对特定行业报价 BOM 表的硬编码查询，保持表格引擎对全行业所有类型表格的 100% 纯粹通用性。
3. **`backend/tests/unit/test_bid_filler_worker.py`**：
   - 使用抽象通用占位符（`条款A`、`条款B`）进行单元测试，验证伪语法被 100% 通用规则拦截。

### 4. 验证结果
- 单元测试验证纯通用规则拦截成功，2D 矩阵写盘 100% 通过（`GENERIC VALIDATION TESTS ALL PASSED 100%`）。

## 实质性要求响应对照表路径提取与动态表头感知修复

### 1. 问题背景
《技术要求响应及偏离表》填报正常，但《第四章项目需求中实质性要求响应对照表》（3 列表格）未能正常填入内容。

### 2. 根本原因定位
1. **Markdown 表格路径列偏移**：大模型在终端总结末尾输出了第二张展示性表格（`| 序号 | 实质性要求 | 是否响应 |`），原逻辑按固定列号提取 `cells[1]`，误将中文条款内容判定为 DOM 路径，导致写盘时定位不到节点而静默丢弃；
2. **列数假设失配**：原工作流 Prompt 写死了 5 列偏离表规则，而实质性对照表仅为 3 列，造成大模型装配数据时的冲突。

### 3. 改动明细
1. **`backend/app/agents/bid_filler_workers.py`**：
   - 升级 `_parse_proposals` 中 Markdown 表格的 DOM 路径识别机制，必须动态检索包含 `/body/`、`/tbl[`、`/p[` 的真正路径列；
   - 升级工作流 Prompt 为**通用动态表头感知**，根据实际检测到的表头列数（3 列、4 列、5 列）自适应装配与对齐数据。

### 4. 验证结果
- 针对《第四章项目需求中实质性要求响应对照表》的 20 条提案提取验证 100% 成功提取；
- 全量单元测试 10 项全部通过（`10 passed in 17.30s`）。

## 实质性要求对照表单单元格提案双路融合保护修复

### 1. 问题背景
运行后《技术要求响应及偏离表》已正常填入内容，但《第四章项目需求中实质性要求响应对照表》在生成的 Word 文档中除最后 1 格外其余内容全部为空白。经诊断报告确认：大模型已完整分析并生成了 20 个单元格全部 10 项实质性要求与“是”响应提案，但写盘后内容丢失。

### 2. 根本原因定位
1. **整表路径正则锚点缺失**：Worker 在执行【Tool-First 双路提案融合】时，原逻辑使用 `re.search(r'^(/body/tbl\[\d+\])', p_path)` 判断是否为整表 2D 矩阵提案；
2. **单单元格路径误触整表清理**：该正则缺少结尾锚点 `$`，导致任意单单元格路径（如 `/body/tbl[4]/tr[11]/tc[3]/p[1]`）均被错误匹配为整表 `/body/tbl[4]`；
3. **同表其他单元格被误删**：代码误认为捕获了整表覆盖提案，从而将 `proposals_dict` 中同表前置提取的 19 个单元格提案全部作为“旧行”删除，最终仅剩最后 1 个单元格提案提交写盘。

### 3. 改动明细
1. **`backend/app/agents/bid_filler_workers.py`**：
   - 严格整表路径判定：增加必须为 `table_rows` 类型或全字精确匹配 `^/body/tbl\[\d+\]$` 的前置约束；
   - 确保单单元格级提案（`/body/tbl[N]/tr[X]/tc[Y]/p[Z]`）在双路融合时 100% 安全合并保留，互不误删；
   - 优化行级模糊路径过滤规则，放行 `sentence_batch` 与含多列分隔符的行级提案。
2. **`backend/tests/unit/test_bid_filler_worker.py`**：
   - 新增 `test_dual_path_merge_substantive_table_cell_proposals_should_preserve_all_cells` 单元测试，模拟实质性要求对照表 20 个单元格提案在双路融合下的全量保留与 100% 成功刷盘到 Word。

### 4. 验证结果
- 全量 Worker 单元测试 11 项全部通过（`11 passed in 17.05s`）。
