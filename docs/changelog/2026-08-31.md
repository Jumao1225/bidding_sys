### 1. MinerU 上传接口输入校验与离线联调测试

**问题背景**

- `POST /api/v1/mineru/parse` 的 API 测试直接调用 MinerU 云端服务，离线或代理不可用时会重试后返回 500，导致接口测试不稳定。
- 接口未限制 `parse_mode` 和上传文件扩展名，无效输入会进入解析服务后才失败。
- 上传文件名未显式剥离路径部分，临时文件清理失败时也没有记录异常。

**问题根因**

- 测试没有隔离外部网络边界，把第三方服务可用性与 FastAPI 路由契约混在同一个测试中。
- 路由参数使用普通字符串，缺少 FastAPI/Pydantic 可执行的枚举约束和文件格式白名单。

**后端修改**

- 在 `backend/app/api/endpoints/mineru.py` 将 `parse_mode` 约束为 `auto`、`txt`、`ocr`，无效值由请求校验层返回 422。
- 增加 PDF、DOC、DOCX 扩展名白名单；不支持的文件返回 400，并记录用户、文件名和扩展名。
- 使用安全文件名生成临时路径，并为临时文件清理失败补充异常堆栈日志。

**测试验证**

- 重构 `backend/tests/api/test_mineru_api.py`：保留真实 ASGI 路由、鉴权覆盖、文件上传、响应模型和 Markdown 预览，仅模拟 MinerU 云端解析边界。
- 新增路径型文件名、无效解析模式、不支持文件格式、空文件四类安全、异常与边界场景。
- `pytest tests/api/test_mineru_api.py -q -s -p no:cacheprovider --disable-warnings`：6 个用例全部通过。

### 2. 文档解析错误改为页面内友好提示

**问题背景**

- 招标文件解析失败时，`UploadBox` 使用浏览器原生 `alert` 直接展示后端错误。

**问题根因**

- 前端未对解析任务、SSE 连接和请求提交三类错误进行统一映射与脱敏。
- 错误展示与原始诊断信息混在同一字符串中，既影响体验，也泄露无意义的技术细节。

**前端修改**

- 新增 `frontend/src/utils/analysisError.ts`，统一提取并映射重试耗尽、超时、模型认证、进度连接中断和请求失败等错误。

- 对 `RetryError`、`Future`、内存地址和异常栈特征进行脱敏；原始错误仅通过浏览器控制台结构化记录，便于联调排查。
- 切换文件、重新解析或清空结果时同步重置错误状态，错误卡片支持关闭和直接重新解析。

**测试验证**

### 3. 标书撰写进度流与页面并发访问隔离

**问题背景**

- 标书撰写页面建立 SSE 后，后端每秒在异步事件循环中同步查询审计日志；其他页面请求可能因此被延迟或无法及时返回。
- SSE 路由注入的数据库依赖会跟随长连接生命周期保留，前端快速切页时，延迟启动的 SSE 回调还可能重新创建僵尸连接。

**问题根因**

- `get_bid_fill_worker_logs` 是异步路由，但内部直接执行同步 SQLAlchemy 查询。
- `stream_bid_fill_worker_logs` 在异步生成器内直接执行同步查询，并额外保留了不需要的请求级数据库依赖。
- `AgentAuditPage` 的 200ms 延迟启动定时器未保存和取消，组件卸载后仍可能打开新的 EventSource。

**后端修改**

- 新增 `_query_bid_fill_logs`，统一创建、关闭日志查询会话，并把过滤失败降级逻辑保留在线程池任务内。
- 将日志查询接口改为同步路由，由 FastAPI 自动放入线程池执行。
- 移除 SSE 路由的数据库与用户依赖，将每轮日志查询通过 `run_in_threadpool` 执行，避免同步 I/O 占用主事件循环。
- 同步调整审计报告接口对日志查询函数的调用方式。

**前端修改**

- 在 `AgentAuditPage` 保存 SSE 延迟启动定时器；切换文档、组件卸载或 POST 启动失败时，统一取消定时器并关闭 EventSource。

### 8. 修复资格证明字段及图片锚点被写盘保护误拦截

**问题背景**

- 资格证明章节 Worker 已生成 13 条提案，但带有纯字段标签、句中空白槽位或动态资质名称后缀的提案仍被写盘保护或图片锚点校验拦截。

**问题根因**

- 写盘保护只识别下划线、冒号后的空格等显式槽位，无法识别“字段标签：”或句中连续空白。

- 字段别名改为只接受完整别名匹配，并按最长有效别名优先，避免短标签误归类。
- 图片锚点统一去除空白/标点，并允许同一动态材料名称的有效连续主体片段匹配，仍保留目标段落与图注的双重校验。

### 9. 修复封面标签-only 日期槽位被写盘保护拦截

**问题背景**

- 封面段落原文仅保留 `日 期 ：` 字段标签时，Worker 已生成 `2026年6月30日` 日期提案，但 DOM 写盘阶段将其判定为固定格式原文，导致 5 条提案最终只写入 4 条。

**问题根因**

- `_has_fillable_slot_marker` 对无下划线、无冒号后连续空格的纯字段标签仅通过 `ALIAS_MAP` 识别。
