## 2. 投标文件切分与多级章节 Path 继承逻辑重构
- **改动说明**：针对投标文件评分过程中原文件切分不精准、目录页碎片污染及多层级（L1/L2/L3）父子章节结构丢失的问题，进行了全面的提取与切分算法优化。
- **重构细节**：
  1. **目录页（TOC）隔离**：在 `_group_markdown_text_by_chapter` 中增加目录区域探测与隔离机制，防止前几页的目录项（带 `... 49` 引符）被误判为正文大章切割出无效碎片。
  2. **多级标题层级与 Section Path 堆栈**：实现 `_detect_heading_level`，支持一级根大项（`一、`）、二级大章（`第一章`）与三级子节（`第一节`）识别，通过动态栈实时生成 `section_path`（如 `八、设计方案、施工方案 > 第一章 设计方案 > 第一节`）。
  3. **Chunk 头部上下文注入**：为投标文件的所有段落与表格切片顶部强行拼接 `[所属章节: {section_path}]`，消除打分 LLM 断章与归属混淆幻觉。
  4. **元数据持久化**：将完整的 `section_path` 存入 `DocChunk.section_title` 与 `trace_info` 中，支持打分 Agent 精准结构检索。
  5. **非 TOC 证书标题防污染与堆栈强纠偏**：以开头【目录（TOC）白名单】作为顶级 Level 1 根大项的唯一权威判定，防止诸如“中国合格评定...证书”、“身份证”、“施工合同”等非目录附件标题误升为 Level 1 霸占根节点，彻底解决后续正文大章（如“第七章 售后服务”、“第八章 质保承诺”）被错误前缀污染的问题。
  6. **解决 MinerU 输出 `## ` 抢占 Level 2 导致根大项锁死的问题**：重构 `_detect_heading_level` 检测优先级，将一~十三顶级汉字大项（如 `一、`、`六、`、`七、`）及 TOC 目录根节点的识别顺序提升至原生 Markdown `#` / `##` 之前，确保 PDF 解析引擎输出的 `## 六、...` 能正确触发 Level 1 根大项切换，彻底消除了 `五、常用零件及耗材报价表` 锁死堆栈霸占后续全篇大章的 Bug。
  7. **豁免《三、资格证明文件》及防非 TOC `#` 标题击穿根节点**：修复《三、资格证明文件》因包含“证明”二字被误判降级的问题，并增加 TOC 根节点保护机制（当 `stack[0]` 为主目录合规根大项时，禁止非 TOC 的 `# 营业执照`、`# 审计报告` 清空根节点），确保几十页的审计报告、利润表、执业证书、社保证明与建造师证书 100% 紧密包裹在《三、资格证明文件》父节点树下。
  8. **标书评分专属哑巴切片过滤与空标题压缩**：在 `extractor_service.py` 仅针对 `doc_type == "bid"` 的标书评分切分流程中禁止生成无正文的 0 字哑巴标题 Chunk；同时在 `bid_scorer_tools.py` 结构索引检索中自动跳过字数 < 15 的纯标题 Chunk，确保打分 Agent 100% 抓取到有正文文字内容（如 `维保服务范围`、`日常点检`、`产品维护与保养方法`）的丰富切片进行大模型评估，杜绝误判 0 分。
  9. **启用全章闭环盲拉机制 (Full Chapter Family Retrieval)**：在 `bid_scorer_tools.py` 结构检索中，当通过关键字命中某个种子切片（如 `第六章 培训方案 > 第一节 现场操作培训`）时，自动提取其章节父路径前缀（`七、设计方案... > 第六章 培训方案`），并全量顺序拉取该大章下的全部连续子切片（第一节~第五节全量包含），彻底消除“正文里有但检索只抓到了 1 个小节，导致 LLM 误以为正文缺失扣分”的顽疾。

## 3. Agentic Active RAG（智能体自主提问与动态上下文补齐体系）上线
- **改动说明**：重构打分 Agent 评估逻辑，将以往死板单次 RAG 上下文提升为具身智能体的“自主反思追问与动态上下文扩展”架构。
- **重构细节**：
  1. **初审缺项提取 (`extract_missing_keywords_from_round`)**：在第 1 轮评估后，Agent 自动检查失分扣分项中的 `deduction_reason`，提取出形如“缺少日常运行管理”、“未包含施工工艺流程”等缺失关键词。
  2. **二次反查与上下文动态膨胀 (`active_refine_context_with_keywords`)**：拿缺失关键词自动发起二次数据库全域钻取，并将补充到的有效正文切片去重合并到 `bid_content` 尾部。
  3. **终审中位数选优 (`specialist_score_node`)**：第 2 轮与第 3 轮评估基于补全后的 100% 完整上下文重新裁判，彻底解决了因初次检索遗漏导致跑多轮依然判定 0 分/3 分的难题。
- **涉及文件**：
  - `backend/app/agents/tools/bid_scorer_tools.py`
  - `backend/app/agents/bid_scorer_agent.py`
  - `backend/tests/unit/test_agentic_rag.py`
