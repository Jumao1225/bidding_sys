- **后端修复**：

  - 在 `backend/app/api/endpoints/bid_generator.py` 的后台落盘逻辑完成后追加了 `master_completed` 终态事件。
- **前端修复**：

### 6. 解决 Office CLI 进程占用与句柄锁悬挂问题
- **问题根因**：
  - `OfficeCLIService._run_command` 的 `subprocess.run` 未设置 `timeout` 参数，遭遇大文件或异常挂起时会导致无期限锁死线程。
  - 在后台 Worker 频发操作 Word DOM 节点或插入资质图片时，如果 `officecli.exe` 或 `soffice.exe` 孤儿进程未彻底退出，Windows 会抛出 `PermissionError` (WinError 32) 文件独占锁异常。
- **后端修复**：
  - 在 `backend/app/services/office_cli_service.py` 中为 `_run_command` 增加了 `timeout=30` 强拦截保护与 `subprocess.TimeoutExpired` 超时解锁机制。
  - 新增 `kill_lingering_processes()` 强杀救援函数，能够自动清理 Windows/Linux 中悬挂残留的 `officecli` 及 `soffice` 孤儿进程，彻底解封 `.docx` 文件锁。
  - 在 `backend/app/agents/tools/bid_db_tools.py` 的 `_safe_save_doc` 捕获 `PermissionError` 时加入自动触发进程清理与救援解封逻辑。
  - 在 `backend/app/api/endpoints/admin.py` 中新增 `POST /api/v1/admin/clean-office-processes` 运维一键清流管理端点。
- **测试验证**：
  - 在 `backend/tests/unit/test_office_cli_service.py` 中补充了 `test_kill_lingering_processes_should_return_integer` 单元测试。

### 8. 架构重构： Worker 纯 Proposal 内存提议 + Master 集中式 1 次原子刷盘
- **问题根因**：
  - 之前 Worker 工具链暴露了直接操作磁盘 `.docx` 文件的接口（如 `officecli_batch_fill_sentence`），当多个 Worker 并发运行调用该工具时，在 Windows 环境下导致了 `PermissionError / WinError 32` 文件句柄独占锁冲突。
- **后端重构**：
  - 在 `backend/app/agents/bid_filler_workers.py` 中，重构 Worker 填报工具为**纯 Proposal 提议注册模式**。Worker 在并发执行阶段仅在内存中组装提案字典，完全脱离磁盘文件 I/O，从物理上彻底封杀文件锁争抢。
  - **[热修复 1]** 修复了 Worker 纯提案模式下 `insert_image` 资质图片提案被丢弃的漏洞：在 `bid_filler_workers.py` 中补充提取图片工具调用的逻辑，并在 `bid_filler_agent.py` 的集中写盘引擎 `fill_docx_proposals_in_dom` 中新增了 `type: "image"` 专属原位图片渲染渲染器，彻底闭环图片填报。
  - **[热修复 2]** 修复了 Worker 纯提案模式下“没有执行写盘，最后下载的标书什么也没有填写”的致命主流程断点：在 `bid_filler_agent.py` 的 `agent_fill_node` 尾部，补齐了收集完 `worker_proposals` 后调用 `_fallback_write_commands` 真正触发主控原子写盘的动作，确保了修改能够真实落盘并被后续 `supervisor_audit_node` 感知。
  - **[热修复 3]** 针对纯 DOM 写盘引擎（`fill_docx_proposals_in_dom`）带来的排版回归问题进行了深度修复：
    - **无差别下划线修复**：由原先“非表格一律加下划线”改为“基于原标书智能探测”，只有当原生占位符包含下划线（`___` 或 `＿＿`）时，才为填入的内容打上 Word 原生 `<w:u>` 标签。
    - **批量插行表格丢失修复**：放开了 DOM 引擎对 `/tbl[N]` 级路径的拦截，针对 JSON 数组类型的表格扩展指令，会在 DOM 切片插值完成后，独立调用 OfficeCLI 执行原生结构化表格扩容，恢复了表格数据填充能力。
    - **图片错位 / 路径幻觉修复**：修复了因 Prompt 工具提示词中错误示例 `/row/cell` 导致大模型产生路径幻觉（应为 `/tr/tc`）的问题，并增强了 `_find_paragraph_by_path` 解析器，使其对 `row` 和 `cell` 关键词向下完全兼容。
  - **[热修复 4]** 修复了 Worker Markdown 总结表格解析器的缺陷与段落覆写逻辑：
    - **重构 Worker 总结表结构**：强制大模型在总结表格新增第 5 列 `提议类型`，使得 `_parse_proposals` 能够准确捕获 `image` 和 `sentence_batch` 标签。解决了此前因类型丢失导致资质图片被当成纯文本插入（出现“📷 插入【...】”字样）的严重 Bug。
    - **段落覆盖重写（Sentence Batch）支持**：在 `fill_docx_proposals_in_dom` 中新增了 `sentence_batch` 类型分支。当遇到长句重写提案时，不再使用残缺的切片匹配，而是直接原子化清空并覆写整段，彻底解决了大模型重写整段授权书时出现的首尾文本严重重复交错问题。
    - **Markdown 污染剥离**：在 `_parse_proposals` 中全局剥离大模型擅自添加的 `**` 加粗标记，防止这些标记原样污染 Word 表格单元格。
