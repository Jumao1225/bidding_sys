# 改动日志 (2026-08-10)

### 1. 样式感知型 Word 解析与 Run 粒度转义引擎 (`docx_parser.py`, `test_docx_style_parser.py`)
- **变更需求**: 解决招投标及合同文档处理中，文本字体格式/样式（加粗、斜体、下划线、红色文字及斜体+下划线组合）在提取纯文本时被丢弃，导致 AI Agent 无法识别样式约束（如：“参考第四章中斜体且带有下划线的文字”）的痛点。
- **改动策略**:
  1. **Run 节点精细渲染 (`docx_parser.py`)**:
     - 在 `DocxParser` 中新增静态渲染函数 `_render_styled_paragraph`，逐 `Run` 节点抽取 `bold`, `italic`, `underline` 及 `font.color.rgb` 属性；
     - 将单一或复合格式无损转义为 HTML/Markdown 语义标记：
       - **斜体 + 下划线** 组合：转义为 `<span class="style-italic-underline"><u>*文本*</u></span>`；
       - **加粗 / 斜体 / 下划线**：转义为 `**加粗**`、`*斜体*`、`<u>下划线</u>`；
       - **字体颜色（如废标红字 `#FF0000`）**：转义为 `<span style="color:#FF0000">...</span>`；
     - 对正文段落及表格单元格（`Table` 节点）全覆盖应用该转义渲染；
  2. **单元测试 (`test_docx_style_parser.py`)**:
     - 编写 3 项单元测试，覆盖基础格式、颜色转义及使用 `python-docx` 真实生成 `.docx` 文件后的无损解析测试。

### 2. Agent 样式定向提取工具开发与 `document_id` 物理路径智能路由 (`style_extractor_tool.py`, `test_style_extractor_tool.py`)
- **变更需求**: 赋予 Agent 按照“章节名称 + 精细字体样式”进行特定条件定向过滤与提取的能力，同时解决 Agent 只有 `document_id` 无法获取物理磁盘路径的瓶颈。
- **改动策略**:
  1. **开发 `@tool extract_text_by_style` 工具 (`style_extractor_tool.py`)**:
     - 支持参数：`document_id`, `file_path`, `chapter_keyword`, `style_type`（支持 `"italic_underline"`, `"bold"`, `"italic"`, `"underline"`, `"bold_red"`）；
  2. **`document_id` 数据库智能解析模块 (`resolve_document_file_path`)**:
     - 内置智能路由解析逻辑，直接接受 `document_id`（如 `"d55ae462-a1a5-4048-91a4-c57e3099ea74"`）并自动通过 `SessionLocal` 去数据库 `DocumentModel` 表检索对应的物理磁盘绝对路径；
     - 提供强健的路径容错逻辑：针对 Agent 将 `document_id` 填入 `file_path` 的误操作及 `.doc` 转 `.docx` 文件路径自动追踪容错；
  3. **单元测试对齐 (`test_style_extractor_tool.py`)**:
     - 编写 5 项单元测试，覆盖无效文件、缺参拦截、真实文件提取及通过 mock DB 基于 `document_id` 自动解析路径的单元测试，8/8 项测试全部通过 (PASSED)。

### 3. Agent System Prompt 样式认知规约植入与多 Agent 工具绑定 (`chat_agent.py`, `bid_filler_workers.py`)
- **变更需求**: 引导 LLM 理解 Markdown 中转义的 HTML 样式标签，并在前台对话与后台标书填报 Worker 中全量打通该工具的使用。
- **改动策略**:
  1. **System Prompt 认知规约 (`chat_agent.py`, `bid_filler_workers.py`)**:
     - 在 `ChatAgent` 与 `Worker Agent` 系统提示词中植入【文档精细样式与格式感知规约 (Style Cognitive Protocol)】；
     - 明确指示大模型将 `<span class="style-italic-underline"><u>*文本*</u></span>` 识别为斜体+下划线，以及在面临诸如“根据第四章斜体带下划线要求填写”时主动调起 `extract_text_by_style` 工具；
  2. **Worker Agent 工具链绑定 (`bid_filler_workers.py`)**:
     - 在 Worker 工厂函数 `build_worker_tools` 的 `worker_tools` 中添加 `extract_text_by_style`，使其与 `officecli_fill_table_rows` / `officecli_batch_fill_sentence` 无缝协同，支持识别后原位填报 Word 标书。
