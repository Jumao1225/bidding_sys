### 5. 隔离标书撰写任务的同步调度操作

- **问题背景**：后端启动 Agent 全自主撰写时，其他页面依赖的接口可能出现加载等待；撰写接口虽然使用独立子进程执行长任务，但任务预留、审计日志清理和 Windows 子进程启动仍直接运行在 FastAPI 异步事件循环中。
- **问题根因**：`backend/app/api/endpoints/bid_generator.py` 的 `trigger_agent_bid_filling` 为异步路由，却同步调用 Redis 锁、SQLAlchemy 数据库操作和 `multiprocessing.Process.start()`；调度阶段的同步耗时会阻塞同一 Web worker 处理其他请求。
- **核心改动**：新增 `_dispatch_agent_bid_filling` 同步调度函数，并通过 `run_in_threadpool` 执行锁预留、旧日志清理、初始状态写入和独立撰写进程启动；子进程启动失败时在线程池内释放预留槽位并保留异常日志，避免任务容量锁泄漏。
- **测试验证**：新增 `test_trigger_agent_bid_filling_slow_dispatch_should_not_block_health_check`，模拟子进程启动耗时 250ms 时验证 `/health` 不被阻塞；运行 `pytest -q tests/unit/test_bid_fill_task_service.py tests/unit/test_bid_fill_log_query.py tests/api/test_bid_generator_api.py`，25 个测试全部通过；`py_compile` 与 `git diff --check` 通过。
- **影响范围**：标书 Agent 撰写的启动调度、Redis 并发控制、初始审计日志记录；撰写子进程执行逻辑及接口返回格式保持不变。

### 10. 统一 httpx/OpenAI 网络请求日志接入 Loguru

- **问题背景**：DeepSeek 请求期间的 `HTTP Request: POST` 日志使用独立的终端格式，与业务 Loguru 日志格式不一致，并可能造成重复输出。
- **问题根因**：`httpx`、`httpcore` 和 `openai` 使用标准库 `logging`，第三方或启动环境可能为其挂载独立 Handler；原有全局拦截逻辑未对这些日志族进行显式清理和绑定。
- **核心改动**：在 `backend/app/core/logger.py` 中新增 `_configure_logger_family`，显式清理 `httpx`、`httpcore`、`openai` 及其子日志器的独立 Handler，统一接入 `InterceptHandler` 并禁止向上重复传播。
- **测试验证**：新增 `backend/tests/unit/test_logger.py`，覆盖第三方 Handler 替换、子日志器去重和标准日志转发；运行 `pytest -q tests/unit/test_logger.py tests/unit/test_console_log_filter.py -p no:cacheprovider --disable-warnings`，8 个测试全部通过；目标文件 `py_compile` 通过。
- **影响范围**：DeepSeek/OpenAI 兼容客户端的控制台与文件日志格式；HTTP 请求调用逻辑、重试策略和业务日志内容不变。
- **涉及文件**：`backend/app/core/logger.py`、`backend/tests/unit/test_logger.py`、`docs/changelog/2026-09-08.md`。
