# 变更日志 - 2026-09-01

## 核心更新

### 1. 修复工程清单被通用章节路由误锁定
- **问题背景**：工程清单提取被通用 Routing 锁定到“第三章 技术规范书”和“第四章 应答文件格式”，导致模型输入上下文不包含“附件1：工程量清单及报价明细”等真实清单表格。
- **问题根因**：工程清单属于多表格结构化提取场景，但未指定章节时仍复用了通用局部章节路由，并将路由返回的章节作为 RAG 硬限定。
- **后端修改**：工程清单未指定章节时跳过通用 Routing，改由当前文档的结构化表格章节发现逻辑选择检索范围；用户明确指定章节时继续保留章节限定。
- **候选章节识别**：新增基于项目名称、规格/项目特征、单位、数量/工程量和报价字段以及数值数据行的通用表格结构评分，优先保留工程量清单候选，降低应答模板仅凭通用关键词获得高分的风险。
- **日志修改**：记录工程清单是否跳过通用 Routing，以及候选章节的表格数、关键词分和结构分，便于核验附件清单是否进入模型上下文。
- **测试验证**：`python -m py_compile backend/app/agents/tools/metadata_tools.py backend/tests/unit/test_metadata_tools.py` 通过；工程清单、表格筛选及元数据定向测试共 `54 passed`；`git diff --check` 无错误。
- **影响范围**：仅调整未指定章节时的工程清单召回范围和候选章节评分，不修改 MinerU 解析器、通用时间/资质/财务等其他提取流程。
- **涉及文件**：

  - `backend/tests/unit/test_metadata_tools.py`
  - `docs/changelog/2026-09-01.md`

### 9. 修复非连续表格片段的分组续接与无关表格串接
- **问题背景**：同一份 PDF 的工程量清单被分页解析为多个不连续 HTML 表格，后续片段缺少表头或首列编码；同时工程量清单后紧邻非计量表，简单按相邻表格继承会把上一张表的分组带入无关表格。
- **问题根因**：跨表继承只判断表格位置，没有验证当前片段是否仍具有工程量清单的连续计量列形态；表内 BOQ 分类路径也没有在成本结果和页面展示链路中完整保留。
- **后端修改**：新增跨表续接判定，基于尾部数值列、点号或中文分组编码及表格行列结构判断是否续接；缺少连续计量形态的无关表格立即清除继承状态。新增原文计量行审计，仅记录模型与原文的差异，不使用固定词表补造数据。同步在成本匹配结果、成本保存请求和文档回读中保留 `part_name`、`group_path`。
- **前端修改**：成本表归一化并展示“表内分组”路径；该路径仅用于 BOQ 分类展示，不参与 BOM 父子树和成本汇总。
- **测试验证**：新增非连续工程表续接、无关品牌表断开和前端分组字段归一化测试；Python 语法检查及差异空白检查通过。后端目标测试中除修正一处过期日志断言外通过；前端完整构建仍受仓库既有未使用变量和类型错误阻塞，新增 Vitest 受当前 Windows 沙箱 `spawn EPERM` 阻塞。

### 15. 移除投标填表外层分区的名称硬编码推断

- **Prompt 修改**：明确区分外层 `section_name` 与表内 `parent_item/root_item/tree_level`，要求结构分组节点与有数量/单位的明细分别处理。
