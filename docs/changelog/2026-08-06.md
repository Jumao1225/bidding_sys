# 改动日志 (2026-08-06)

### 1. 关闭 Review Agent 功能 (`bid_filler_agent.py`)
- **变更需求**: 响应用户指令，完全关闭 Review Agent 的 LLM 写前审查与质检报告生成。
- **改动策略**:
  1. 在 `review_node` 中添加开关 `ENABLE_REVIEW_AGENT = False`；
  2. 彻底禁用 Reviewer ReAct Agent (LLM) 对 Worker 填报提案的改写与二次过滤干预；
  3. Worker Agent 产出的填报提案直通 Python DOM 安全刷盘引擎，100% 原始精准刷入 Word 文档中。

### 2. `@paraId` 属性通配提取与节点匹配修复 (`bid_filler_agent.py`)
- **致命死穴破获**:
  - Worker 输出的提案路径全量采用了精准的 `@paraId=5C86F3E9`（如 `/body/p[@paraId=5C86F3E9]`）；
  - 之前 `_find_paragraph_by_path` 中硬编码尝试使用 `qn('w:paraId')` 提取 ID；
  - 但在 Office OpenXML 规范中，`paraId` 属于 Word 2010+ 的 `w14` 扩展命名空间（`{http://schemas.microsoft.com/office/word/2010/wordml}paraId`）；
  - `w:paraId` 读取永远返回 `None`，导致 `_find_paragraph_by_path` 找不到段落节点返回 `None`，程序静默跳过写入，造成 Word 正文段落全空的致命假象！
- **重构解决**:
  1. 新增 `_extract_element_paraid` 通配提取函数，遍历 XML 节点属性后缀为 `paraid` 的所有键，100% 静态精准匹配 `w14:paraId`；
  2. 测试集 33/33 PASSED 全量验证通过。

### 3. 标书撰写 Agent 架构升级：多子 Agent 划分、空位识别、Office CLI 直写与 Supervisor 闭环把控
- **架构变更**:
  1. 彻底移除原 Review Agent 节点与提案队列中转，架构改为 Supervisor-Worker 双层高效流转；
  2. Worker 子 Agent 获得 Office CLI MCP 写盘工具，可在检索并整合数据后直接将结果原位写入 Word 临时文档；
  3. Worker 自主识别章节内下划线 `______`、括号 `( )` 占位符与空白表格，先整合段落长句所需的所有字段，再调用 `officecli_batch_fill_sentence_tool` 提交原子更新；
  4. 表格填充遵守四大铁律：严格跳过第一行表头、第一列自动注入 `1, 2, 3...` 连续递增序号、检索到的数据项全量追加保证无遗漏；
  5. 引入 **Supervisor 全局质量闭环 (Audit & Repair Feedback Loop)**：
     - Worker 直写完成后，`supervisor_audit_node` 重新探测 Word DOM 结构；
     - 若检出未填槽位，构造针对性 `repair_instructions` 再次派发给相应 Worker 进行专项修复补救（支持设置 `max_repair_rounds` 防死循环）；
     - 质量审核通过后，导出最终 Word 标书与质量报告。

### 4. 注入【模板原文 100% 盲守】最高铁律与实体区分法则 (`bid_filler_workers.py` & `bid_filler_agent.py`)

- **改动策略**:

  2. 在 Worker System Prompt 中注入 **【采购人 vs 招标代理机构 实体区分法则】**：明确区分 `致：_____`（填代理机构全称）与 `参加 _____ 组织的...`（必须填采购人/项目业主单位全称），禁止混淆错挂；


### 5. 表格 DOM 结构正则修复、LLM 专家语义原文核实与高并发网络重试加固 (`bid_filler_agent.py` & `office_cli_agent_tools.py`)
- **表格行数解析 Bug 彻底修复**:
  - **死穴诊断**: 此前 `officecli_fill_table_rows_tool` 在解析表格已有行数时使用了 `matching_rows = [line ... if "/row[" in line]`，而 Office CLI `query_structure("table")` 返回格式为包含 `rows=N` 的单行总结，导致匹配永远失灵回退为 1 行；数据被全量追加到模板底部的 Row 16，下方空行亦无法擦除；
  - **修复落盘**: 改用正则 `re.search(r'rows=(\d+)', line)` 100% 精准识别模板原有的 15 行，引导数据紧贴 `Row 2` 表头向下顺次原位覆盖，并在数据填完后倒序擦除所有余下未用空行。
- **Supervisor LLM 专家语义正确性与原文对齐核实**:
  - 在 `supervisor_audit_node` 终审节点中增加 **LLM 专家语义与原文/DB对齐核查模块**；
  - 自动将已填盘的摘要与企业主档案 `company_profile` 及招标文件 `original_context` 比对，深度核实项目名称、招标编号、投标人名、法人名及投标总报价大写与小写的精准对应度；若发现张冠李戴或数值不对应，打回定向修复。
- **高并发平滑与网络偶发 Connection Error 自动重试**:
  - Worker Agent 增加 `max_retries = 3` 的指数退避重试循环，遇到 API 网络抖动或闪断时自动重试，消除并发 Connection error；
  - 调度层 `max_workers` 并发线程数由 10 优化调小至 4，平滑高并发请求峰值。


### 6. 新增 `get_full_chapter_text` 100% 全量章节原文提取工具 (`rag_service.py`, `rag_tools.py`, `chat_agent.py`, `bid_filler_workers.py`)
- **变更背景**:
  - 现有的 `search_bidding_document` RAG 工具限制了 `top_k=5` 向量切片截断，在提取复杂商务/合同条款时，容易缺失同一章节内的其他段落（如停电赔偿、转包安全约束）；
  - Gemini 网页效果优秀的原因之一在于其获得了整章 100% 的连贯原文。
- **改动策略**:
  1. 在 `RAGService` (`rag_service.py`) 中新增 `get_full_chapter_text(document_id, chapter_name)`，在数据库中按 `DocChunk.section_title` 匹配并按 `chunk_index` 顺序拼接全部切片，零 Top-K 向量截断；
  2. 在 `rag_tools.py` 中暴露 `@tool` 工具 `get_full_chapter_text`；
  3. 在 `ChatAgent` (`chat_agent.py`) 及标书撰写 Worker Agent (`bid_filler_workers.py`) 中完成工具绑定；
  4. 在 Worker Agent 与 ChatAgent 的系统提示词（System Prompt）中注入 **【🔀 交叉章节检索强指引 (Cross-Chapter Retrieval)】**：强制要求在涉及《偏离表》等多章节交叉对照时，必须分别多次调用 `get_full_chapter_text(document_id, chapter_name)` 拿齐相关章节的 100% 全量原文，杜绝单章节截断盲区；
  5. 在 `tests/unit/test_rag_tools.py` 中新增单元测试并 100% 验证通过。
