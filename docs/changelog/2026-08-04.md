# Change Log (2026-08-04)

### 1. 标书填报下划线区域精准控制修复 (`bid_filler_agent.py`)
- **需求与调整背景**: 之前的版本在表格单元格填报内容上也施加了下划线，影响了表格的整洁美观；按用户要求调整策略为：**表格外部的正文段落填报内容保留下划线，表格内部单元格的填报内容取消下划线**。
- **优化与实施细则**:
  1. **差异化下划线策略 (`fill_docx_proposals_in_dom`)**: 遍历填报提案时，通过检查 XPath 路径 `/tbl[N]` 或 DOM 节点的父级 `w:tc` 标签识别节点位置：
     - **表格外部正文段落 (`is_in_table = False`)**: 填报数据槽位应用 `use_underline = True`（自动注入 OpenXML `<w:u w:val="single"/>` 下划线）；
     - **表格内部单元格 (`is_in_table = True`)**: 填报数据槽位应用 `use_underline = False`（确保单元格文字清晰无冗余下划线）。
  2. **自动化测试与断言 (`test_bid_filler.py`)**: 新增 `test_fill_docx_proposals_underline_policy_outside_vs_inside_table` 单元测试，分别断言正文段落生成 `<w:u>` 下划线与表格单元格移除 `<w:u>` 下划线，全量测试 18/18 全部通过。

### 2. 彻底移除静态默认兜底日期逻辑 (`bid_format_filler_service.py`)
- **优化说明**: 按照要求彻底清除了硬编码的缺省兜底静态日期（如 `"2026年06月30日"`）。当系统未提取到数据库中真实的 `投标日期` 或 `日期` 字段时，不再进行任何假数据注入，保持标书原模版的格式状态不变。

### 3. 模板导出彻底剔除残留目录 (TOC) 与卷标行 (`bid_format_extractor_service.py`)
- **问题根因分析**: 原始招标文件（如 Word/WPS 生成）中的目录页可能包含带修饰符的页码（如 `....................-3-`、`....................-55-`）或卷标（如 `"第一卷"`、`"第二卷"`）。先前 `_is_toc_line` 中的页码正则表达式仅匹配纯数字结尾 `\d+$`，导致匹配失败并将目录页末尾的 `"第六章 投标文件格式....................-55-"` 误判定为正文起点，从而在导出的《投标文件格式模板.docx》首页残留了整套招标文件的目录大纲。
- **优化与精准保证说明**:
  1. **增强 TOC 目录与卷标正则**: 扩展 `_is_toc_line`，支持对 `-3-`、`-55-`、`55页` 等各类修饰符页码及 `"第一卷"`、`"第二卷"` 等卷标行的精准识别；
  2. **DOM 切片头部自动修剪**: 在 `_slice_docx_natively` 与 `_slice_text_by_keywords` 中加入头部残留目录节点自动剪除循环，100% 确保导出的 Word 文件首页直接从正文 `第六章 投标文件格式` 纯净开始，彻底剔除招标文件的残留目录；
  3. **单元测试验证**: 更新 `test_bid_format_extractor.py` 中的 `test_is_toc_line_should_correctly_identify_table_of_contents_lines` 单元测试，断言通过。

### 4. Worker Agent 虚构假日期防幻觉封杀规约 (`bid_filler_workers.py`)
- **问题根因分析**: 在智能撰写过程中，大语言模型（LLM）面对段落末尾的 `“日期：____年___月___日”` 节点时，受通用训练语料补全习惯影响，在数据库查无真实开标/投标日期时自动输出了假日期文本 `"2026年6月30日"`。
- **优化与精准保证说明**:
  1. **Worker System Prompt 下达【防幻觉与伪造日期封杀法则】**: 强制约束 Agent，当从 DB 中查不到真实日期或业务数据时，`proposed_text` 必须严格设为 `"[待补充]"`；
  2. **写盘强拦截保护**: 当 `proposed_text` 为 `"[待补充]"` 时，底层 DOM 填报引擎自动跳过覆写，100% 保留标书模板原有的 `____年___月___日` 空白格式，严禁捏造假日期。

### 7. 智能解析交互升级：右侧卡片一键平滑跳转定位左侧原文段落 (`UploadBox.tsx`)
- **优化说明**: 为右侧【🎯 履约盘点】与【⚠️ 风险提示】卡片增加了高精度跳转定位功能（[UploadBox.tsx](file:///d:/Myproject/bidding_sys/frontend/src/components/UploadBox.tsx)）：
  1. **多词切片重合度打分算法 (Keyword Overlap Scoring)**: 引入滑窗切词与业务权重计算机制（如“联合”、“投标”、“不允许”加权），完美解决“本项目不允许联合投标”（卡片标题）与“本项目不允许联合体投标。”（标书原文）之间因一字之差而无法定位的问题；
  2. **高精度段落/句子锁定 (排除整页容器)**: 过滤掉 Word (`.docx-wrapper`) 与 PDF 渲染树中的包围大容器 (`section`/`article`/`div`)，精确定位到具体的 `<p>` 段落或 `<span>` 文本行；
  3. **原文件预览 DOM 居中滚动与琥珀黄脉冲高亮**: 调用 `scrollIntoView({ behavior: 'smooth', block: 'center' })` 确保目标句子完美居中，并为该具体句子施加 `ring-4 ring-blue-500 bg-amber-200` 琥珀黄高亮脉冲光圈。

### 8. 原文件预览加载双重兼容修补 (`UploadBox.tsx`)
- **问题根因分析**: 之前 `SmartDocViewer` 内嵌原文件预览器仅检查单次会话上传生成的 `taskId`。当用户在历史记录、重新刷新页面或通过 `document_id` 恢复文档解析时，`taskId` 变量为 `null`，导致组件进入无限等待 `"正在加载原文件..."` 状态。
- **优化说明**: 在 `UploadBox.tsx` 中构造 `activeDocOrTaskId = taskId || result?.document_id || result?.id || initialTaskId` 兼容变量，使原文件预览器支持基于 `document_id` 恢复渲染，100% 修复了历史记录或重新刷新时原文件预览缺失的问题。

### 9. 原文件预览新增实时动态缩放与双向滚动控件 (`UploadBox.tsx` & `SmartDocViewer.tsx`)
- **场景需求**: 招标文件（Word/PDF）中常包含超宽格式表格（如《九、项目负责人及其他人员介绍》等十余列的人员资质表格），在窄视口下容易被截断显示不全。
- **功能特性**:
  1. **缩放比例控制工具栏**: 在【原文对照区】顶部加入 `[-]` / `[显示比例%]` / `[+]` 交互按钮，支持 50% ~ 200% 范围以 15% 为步长平滑缩放；
  2. **双向滚动条无障碍查看**: 解锁 `overflow-auto custom-scrollbar`，超宽表格缩小后可一览全貌，放大后可平滑横向/纵向双向滚动阅览；
  3. **PDF & Word 渲染引擎双重适配**: 对 Word (Docx) 视图赋予容器 CSS `zoom: scale` 动态缩放；对 PDF (`react-pdf`) 视图赋予 Page `targetWidth` 动态物理宽度重绘。

### 10. Review Agent 深度质检引擎升级：先审后写 + 自动修正 (`review_engine.py` & `bid_filler_agent.py`)
- **核心架构变更**: 将 `review_node` 从原来的「先写后审（仅生成报告）」重构为「**先审后写 + 发现问题自动修正**」。审查结果直接决定哪些 proposal 能被写入、哪些需要自动修正、哪些被跳过标记为待人工补充。
- **新增模块 `review_engine.py`**: 独立的深度质检引擎模块，包含 5 条规则化审查管线（纯 Python，零 LLM 消耗）+ 1 个自动修正管线：
  | 管线 ID | 名称 | 职责 |
  |---------|------|------|
  | R1 | `check_unfilled_slots` | 必填项遗漏检测：扫描 Word 中残留的 `____`、`[待补充]`、空白单元格 |
  | R2 | `check_data_consistency` | 数据交叉一致性校验：同一字段跨章节填写值是否一致 |
  | R3 | `check_financial_accuracy` | 财务数据准确性校验：总价 vs 分项求和、大写金额 vs 小写金额 |
  | R4 | `check_format_compliance` | 格式合规性校验：日期格式、公司名完整性 |
  | R5 | `check_scoring_coverage` | 评分项覆盖率检查：与 `score_tree` 做结构化详细比对 |
  | R6 | `auto_fix_proposals` | 自动修正管线：对问题 proposals 进行确定性修正或标记跳过 |
- **回退策略**: 自动修正失败时，跳过该字段不写入，标记为 `[待人工补充]`。
- **增强 `officecli_query_context` 工具**: 同时查询 `paragraph` + `table` 两种 selector，解决原来只能查段落、看不到表格内容的问题。
- **Schema 扩展**: 新增 `ReviewFinding` Pydantic 模型；`BidFillAuditReport` 新增 `review_findings` 和 `review_summary` 字段。
- **单元测试**: 新增 `test_review_engine.py`，覆盖 18 个测试用例（R1~R6 + 工具函数），全部通过。
