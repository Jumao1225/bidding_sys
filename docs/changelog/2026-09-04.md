### 5. 修复 DOCX 最高限价“万元”单位丢失
- **问题背景**：DOCX 转换后的文本会将 `2600万元` 拆分为 `<u>2600</u><u> 万元</u>`，金额解析正则只提取到 `2600`，导致页面显示为 `2,600.00元`。
- **问题根因**：财务金额解析在识别金额和单位前未清理 HTML 格式标签，单位未能进入正则的 `unit` 分组。
- **核心改动**：修正 `normalize_markup_text` 对 HTML 开始/结束标签的完整清理，并在金额候选文本中复用该归一化逻辑后再执行金额与单位识别；保持后端金额统一按“元”落库。
- **数据修复**：依据文档 `81fb2188-a5aa-46b4-a839-3164f3f0a41f` 的原文证据，将已有财务元数据中的最高投标限价从 `2600` 修正为 `26000000` 元，并同步修正成本分析中的预算数值、预算文案和超限状态。
- **测试验证**：新增 DOCX 标签拆分场景回归测试，确认 `2600万元` 解析为 `26000000.0` 元。
- **涉及文件**：
  - `backend/app/services/metadata/financial_service.py`

### 15. 允许未定价的手动新增项参与批量价格匹配

- **核心改动**：仅当手动新增项单价为空或小于等于 0，且未被明确手动修改时，才将其补充到 CostAgent 的批量匹配输入；已有人工价格或明确手动修改的项继续保持人工结果，不被自动覆盖。
- **匹配与合并**：补充项沿用名称、规格、数量、单位、父子关系和稳定 `node_id`；批量匹配结果通过稳定节点 ID 回写，保留原有 BOM 结构和层级汇总逻辑。
- **前端提示**：新增成本分项和新增子项表单均提示“0 元将在下一次批量重匹配时尝试匹配价格库，正价按人工定价保留”。
- **测试验证**：后端成本服务与 CostAgent 定向测试 `15 passed`；前端 BOM 分组单元测试 `49 passed`；TypeScript `tsc --noEmit` 通过。
