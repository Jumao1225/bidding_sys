# 变更日志 - 2026-08-27

## 核心更新

### 1. 标书生成与 Agent 控制台一体化整合与视觉细节优化
- **问题背景**：
  1. 控制台之前被拆分成 4 个分散的浮动黑盒卡片（顶栏、通知栏、指令统计区、工作台），导致中间出现浅色底间隙，视觉上不够连贯；
  2. 在合并为单个 Mega 控制台外层容器时遗漏了闭合 `</div>` 标签，引发 `JSX element 'div' has no corresponding closing tag` 编译报错。
- **核心改动**：
  - **4 块合一的大型一体化控制台（Mega-Console）**：
    - 将「顶栏任务编排」「状态通知」「指令输入与 4 大指标统计」「章节履历与思考决策主工作台」4 个独立板块全部统一收纳进同一个圆角大卡片（`rounded-3xl border border-slate-800/90 bg-slate-950 divide-y divide-slate-800/80`）内；
    - 消除所有原本横亘在中间的浅色背景缝隙，形成完整、连贯、高科技质感的一站式控制台面板。
  - **修复 JSX 闭合标签**：在工作台结构闭合处补全 Mega-Container 的 `</div>` 标签，消除 TypeScript 编译错误。
- **测试验证**：前端 `npm exec vite build` 重新编译成功（1.96s），零报错。
- **涉及文件**：
  - `frontend/src/pages/AgentAuditPage.tsx`
  - `docs/changelog/2026-08-27.md`

### 2. 租户管理员支持分配租户管理员权限与分配账号交互优化
- **问题背景**：
  1. 系统管理中分配新账号时，原后端接口限制租户管理员只能创建普通用户（`user`），无法为本租户指派协助管理的租户管理员；
  2. 前端分配账号弹窗对租户管理员展示了禁用的租户下拉框，交互冗余且存在困惑。
- **核心改动**：
  - **后端权限放宽**：
    - 在 [admin.py](file:///d:/Myproject/bidding_sys/backend/app/api/endpoints/admin.py) 的 `create_user` 接口中，放宽租户管理员（`tenant_admin`）创建用户的角色限制为 `["user", "tenant_admin"]`；
    - 依然保留严格的多租户安全隔离边界：禁止跨租户创建用户，禁止越权创建平台管理员（`admin` / `platform_admin`）。
  - **前端弹窗与交互优化**：
    - 在 [SystemAdmin.tsx](file:///d:/Myproject/bidding_sys/frontend/src/pages/admin/SystemAdmin.tsx) 分配账号弹窗中，租户管理员操作时自动绑定当前租户 `tenant_id`，隐藏租户下拉框并展示优雅的只读提示卡片（“当前租户 / 本企业 (本租户隔离)”）；
    - 开放角色下拉框，租户管理员可自由选择分配“普通用户”或“租户管理员”；
    - 平台超级管理员保留全系统租户下拉选择与角色分配功能。
- **测试验证**：
  - 更新 [test_admin_permissions.py](file:///d:/Myproject/bidding_sys/backend/tests/api/test_admin_permissions.py) 中的 `test_tenant_admin_should_create_user_and_tenant_admin_in_own_tenant` 测试用例；
  - 运行 `pytest tests/api/test_admin_permissions.py -v`，7 项多租户与管理员权限测试全部通过（7 passed）。

### 3. 系统管理中心新增账号删除与启用/停用状态切换功能
- **问题背景**：
  - 系统管理中心此前仅支持创建账号、修改密码与变更租户，缺乏账号状态管理（停用/启用）与物理删除功能，无法满足离职封禁和错误账号清理需求。
- **核心改动**：
  - **数据层与 Schema 扩展**：
    - 在 [user.py (schemas)](file:///d:/Myproject/bidding_sys/backend/app/schemas/user.py) 中新增 `UserUpdateStatus` 模型；
    - 在 [user.py (CRUD)](file:///d:/Myproject/bidding_sys/backend/app/db/crud/user.py) 的 `CRUDUser` 中新增 `remove` 物理删除方法。
  - **后端 RESTful 接口与严格权限防御**：
    - 在 [admin.py](file:///d:/Myproject/bidding_sys/backend/app/api/endpoints/admin.py) 中新增 `PUT /api/v1/admin/users/{user_id}/status` 与 `DELETE /api/v1/admin/users/{user_id}` 接口；
    - **自身保护拦截**：禁止管理员删除或停用当前登录的自身账号（400）；
    - **租户隔离拦截**：租户管理员只能删除/停用本租户账号，跨租户操作直接 403 拦截；
    - **越权保护拦截**：租户管理员禁止删除/停用平台超级管理员账号（403）。
  - **前端表格操作列与交互优化**：
    - 在 [SystemAdmin.tsx](file:///d:/Myproject/bidding_sys/frontend/src/pages/admin/SystemAdmin.tsx) 中新增 `handleToggleStatus` 与 `handleDeleteUser`；
    - 表格操作列支持“停用 / 启用”与“删除”按钮，带危险操作二次确认；
    - 针对当前登录账号自动隐藏自删/自停用按钮并标识“我”，防止误操作。
- **测试验证**：
  - 在 [test_admin_permissions.py](file:///d:/Myproject/bidding_sys/backend/tests/api/test_admin_permissions.py) 中新增 `test_admin_status_toggle_permissions` 与 `test_admin_delete_user_permissions` 测试用例；
  - 运行 `pytest tests/api/test_admin_permissions.py -v`，全量 9 项权限与管理测试全部通过（9 passed）。
- **影响范围**：

    - 提供「停用 / 启用」按钮，带警告二次确认弹窗；
