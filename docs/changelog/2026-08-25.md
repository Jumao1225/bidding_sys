## 租户管理员权限与创建入口

- 新增 `tenant_admin` 角色；保留历史 `admin` 角色作为平台管理员，兼容现有管理员账号。
- 系统管理的“分配新账号”支持创建租户管理员；平台管理员可为任意租户创建，租户管理员只能创建本租户普通用户。
- 租户管理员只能查看和修改本租户账号，不能访问全局租户管理、跨租户创建用户或变更用户所属租户。
- 前端系统管理入口对平台管理员和租户管理员开放，并根据身份显示全局租户管理或本租户账号管理。
- 新增管理员权限 API 测试，覆盖租户隔离、角色限制和平台管理员创建租户管理员场景。

### 7. 统一大模型调用的租户配置与 BOM 并发租户传递

- **问题根因**：BOM 成本核算在 `cost_agent.py` 中使用 `ThreadPoolExecutor` 并发调用大模型，线程未继承 `current_tenant_id`，导致运行时回退读取 `.env` 中的全局 API Key；部分 Agent 还通过 `raw_llm` 访问启动时创建的全局客户端。
- **核心改动**：`LLMService.get_llm()`、结构化输出、文本生成和流式聊天接口支持显式传入 `tenant_id`；所有业务代码中的 `raw_llm` 调用改为按租户获取 LLM 客户端。
- **BOM 修改**：`backend/app/agents/nodes/cost_agent.py` 将租户 ID显式传入每个并发批次的大模型调用，避免并发线程丢失租户上下文。
- **日志与安全**：新增租户、模型、API 地址和 API Key 尾部四位的脱敏运行日志，不记录完整 API Key。
- **测试验证**：Python 语法检查通过；`tests/unit/test_llm_service.py` 与 `tests/unit/test_cost_agent.py` 共 7 个测试通过；业务代码中 `raw_llm` 仅保留在 `LLMService` 内部兼容实现。
- **涉及文件**：`backend/app/services/llm_service.py`、`backend/app/agents/nodes/cost_agent.py`、`backend/app/agents/bid_filler_agent.py`、`backend/app/agents/bid_filler_workers.py`、`backend/app/agents/bid_scorer_agent.py`、`backend/app/agents/chat_agent.py`、`backend/app/agents/supervisor.py`、`backend/app/agents/orchestrator.py`、`backend/app/agents/tools/bid_scorer_tools.py`、`backend/app/services/bid_scorer_service.py`、`backend/app/services/company_qualification_service.py`、`backend/app/services/bid_format_extractor_service.py`、`backend/app/agents/nodes/strategy_agent.py`、`backend/tests/unit/test_llm_service.py`、`backend/tests/unit/test_cost_agent.py`。
