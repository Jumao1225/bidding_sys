### 23. .doc 转 .docx 格式转换 [WinError 2] 异常修复与多级降级策略 (`extractor_service.py`, `test_doc_converter.py`)
- **报错原因**: 用户上传 `.doc` 旧格式文档时，系统调用 `subprocess.run(["soffice", ...])` 进行格式转换，由于 Windows 系统环境下 `soffice` 未添加到环境变量 PATH 中，触发 `FileNotFoundError: [WinError 2] 系统找不到指定的文件。` 导致底层解析 Worker 任务抛错崩溃。
- **改动策略**:
  1. **多级目录与备选引擎查找 (`extractor_service.py`)**:
     - 在 `shutil.which("soffice")` 未命中的情况下，增加在 Windows 常见默认安装路径（`C:\Program Files\LibreOffice\program\soffice.exe` 等）及 `SOFFICE_PATH` 环境变量中自动检索 `soffice.exe` 路径的逻辑；
  2. **MS Word (win32com) COM 接口降级**:
     - 当系统无 LibreOffice 时，在 Windows 环境自动降级使用 `win32com.client` 调用本地 Microsoft Word COM 自动化接口（`wdFormatXMLDocument`）无损完成 `.doc` 到 `.docx` 的转换；
  3. **doc2docx 第三方库降级**:
     - 增加 `doc2docx` 库的导入与转换尝试作为第三重容错保护；
  4. **优雅归因异常提示**:
     - 若所有转换引擎均不可用，捕获原始异常并汇总为带有明确排查建议的 `RuntimeError`，杜绝未处理的裸 `WinError 2` 报错；
  5. **单元测试集成 (`test_doc_converter.py`)**:
     - 在 `tests/unit/test_doc_converter.py` 中编写单元测试，覆盖已有文件直接返回、LibreOffice 路径指令触发以及引擎全缺失时的优雅报错。

### 24. 旧版 .doc 原文件预览红叉报错修复与后端二进制流重定向 (`analysis.py`, `LocalDocxRenderer.tsx`, `UploadBox.tsx`)
- **报错原因**: 用户上传 `.doc` 二进制旧格式文档并切换至【原文件预览】时，由于浏览器与 `docx-preview` 仅支持标准 OpenXML `.docx` 本地解析，`DocViewer` 无法匹配本地渲染器，自动降级调起微软在线预览组件（`view.officeapps.live.com`）。微软公网服务器无法访问 `http://localhost:8000` 本地地址，引发 iframe 挂载失败并显示红叉 (❌) 图标。
- **改动策略**:
  1. **后端预览接口重定向交付 (`analysis.py`)**:
     - 在 `/api/v1/analysis/download/{task_id}` 原文件下载/预览接口中，当请求文件为 `.doc` 格式时，自动重定向并交付已转换的 `.docx` 文件流（如不存在则现场调用 `convert_doc_to_docx` 进行轻量转换）；
  2. **前端文档类型归因与本地渲染拦截 (`LocalDocxRenderer.tsx`, `UploadBox.tsx`)**:
     - 在 `LocalDocxRenderer.fileTypes` 中增加 `doc`, `msword` 匹配规则；
     - 在 `UploadBox.tsx` 的 `viewerDocuments` 中将 `.doc` 文件的预览扩展名归一化为 `.docx`，确保 `DocViewer` 优先触发本地 `docx-preview` 引擎，实现 100% 本地极速无缝渲染，不再依赖任何公网第三方预览服务器。
