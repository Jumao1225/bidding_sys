# 项目改动日志 - 2026-07-24

## 📋 变更概述
本日主要完成了“标书撰写 Agent” MVP 阶段功能——**招标文件“投标文件格式/响应格式”全量提取与 Word (.docx) 自动导出**。实现了双模式架构（原生 Word DOM 切片 + LLM 结构化重建），并且所有生成的 Word 字体样式全量统一为**纯黑色 (`RGBColor(0,0,0)`)**，并在前端系统【投标书草稿生成与交付引擎】面板中添加了专有测试按钮。

* **`backend/app/services/docx_exporter_service.py`**

### 3. 原生 Word DOM 切片与 LLM 双模式提取服务 (Bid Format Extractor Service)
* **`backend/app/services/bid_format_extractor_service.py`**
  - **模式一：原生 Word (.docx/.doc) 直取引擎**：基于正则探照灯定位“投标文件格式”章节起止范围，执行 DOM 节点裁剪克隆，100% 保留原始表格格式与填空下划线，并批量转换字体为黑色（零 Token 消耗，毫秒级响应）。
  - **目录项 (TOC) 干扰排除修复**：新增 `_is_toc_line` 严密判定函数，结合 Word XML 节点特征（如 `w:hyperlink`、`w:pStyle` TOC）与连点线加页码规则（如 `....... 40`），自动判定并排除文档前几页目录项的误杀。
  - **内部格式附件防提前截断修复**：新增 `_is_real_next_main_chapter` 判断函数，区分真正的独立招标大章（如 `第七章 评标办法`）与“投标文件格式”内部的子项附件标题（如 `格式七 授权委托书`、`附件七 承诺函`、`第七部分 商务响应表`），避免提取过程中误将第六章内部的格式子项当成结尾而导致提前截断。
  - **模式二：LLM 结构化重建引擎**：针对 PDF 等格式，定位文本并结合 LLM 输出 JSON，套用黑色字体标准模板导出 Word。
