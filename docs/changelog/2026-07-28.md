## 3. 修复 Agent 同步/异步工具不兼容（StructuredTool does not support sync invocation）

### 问题
- `agent_fill_node` 使用 `agent.invoke()`（同步），但三个 OfficeCLI MCP 工具包装内部调用了异步方法
- DB 工具（`bid_db_tools.py`）是同步 `@tool`，正常工作
- MCP 工具调用异步 `office_cli_mcp_client` 方法时，LangChain 报错 `StructuredTool does not support sync invocation`
- 导致 Agent 两次重试全部失败，流水线未能实际写入 Word

### 改动
- **[MODIFY] `app/agents/bid_filler_agent.py` — `agent_fill_node` MCP 工具包装**:
  - 新增 `_sync_call_async(coro)` 辅助函数，安全地在同步上下文中运行异步协程：
    - 无事件循环 → `asyncio.run()`
    - 有事件循环（FastAPI 上下文）→ `ThreadPoolExecutor` 新线程独立事件循环
  - 三个 MCP 工具（`officecli_query_doc_structure` / `officecli_batch_update` / `officecli_add_table_row`）全部改为通过 `_sync_call_async()` 调用 `office_cli_mcp_client` 异步方法
  - 移除对旧 `mcp_officecli_*` LangChain tool 的 `.invoke()` 包装依赖

## 6. 架构重构：单体 Agent → Multi-Agent Supervisor-Worker 模式

### 问题
- BidFillerAgent 是单体 ReAct Agent（10 工具在一个 Prompt 中）
- 单点故障：Agent 在某章节混乱则全流程失败
- 无并行：所有操作在单个 ReAct 循环中顺序执行
- Token 浪费：Agent 反复读文档结构
- 难以调试：一个大 trace，无法定位哪个章节出错

### 新架构
```
scan_node
  ↓
Supervisor Agent（决策Agent — 4 个决策工具）
  │  读文档 → LLM 四类分类 → 并发派发 Worker → 收集结果
  ↓
┌─── ThreadPoolExecutor 并发 ───┐
│  Worker[投标函]    Worker[开标一览表]   Worker[报价表]   ...  │
│  全部 DB 工具 + OfficeCLI 写盘工具，自主决定调用哪些          │
└────────────────────────────────┘
  ↓
write_docx_node（读回临时文件 → 输出字节流）
```

### 改动

#### 6.1 新增 Worker 工厂模块
- **[NEW] `app/agents/bid_filler_workers.py`**（~220 行）:
  - `_build_worker_tools(docx_temp_path, category, include_table_tools)` — 动态组装 Worker 工具集
    - 所有 Worker 获全部 6 个 DB 直查工具（不硬编码映射，Worker 自主按需调用）
    - 基础 OfficeCLI 工具：`officecli_query_structure` + `officecli_write_text`
    - 表格类章节（needs_data）额外获得：`officecli_add_table_row` + `analyze_word_table`
  - `build_worker_prompt(chapter_title, category, template_text, content_hint, document_id)` — 按章节类别动态生成聚焦 Prompt（~30 行，无具体数据）
  - `run_chapter_worker(...)` — 创建独立 ReAct Agent + 运行 + 返回结果

#### 6.2 重构 Supervisor Agent
- **[MODIFY] `app/agents/bid_filler_agent.py`**:
  - `agent_fill_node` 从 345 行缩减到 ~250 行
  - 删除单体 Agent 的 10 工具创建逻辑（6 DB + 3 OfficeCLI + 1 TableAgent 全塞给一个 Agent）
  - 删除 200+ 行全覆盖 CO-STAR Prompt
  - 替换为 Supervisor Agent（4 个决策工具）：
    - `officecli_query_doc_structure` — 读 Word DOM
    - `analyze_chapters` — LLM 四类分类全文章节
    - `dispatch_chapter_workers` — ThreadPoolExecutor 并发派发 Worker
    - `review_worker_results` — 审查各 Worker 执行结果
  - Supervisor Prompt 从"标书撰写专家"改为"决策调度者"（~40 行）
  - 保留 sandbox 快照备份/恢复 + 重试机制

#### 6.3 废除硬编码工具映射
- 删除旧 `bid_filler_workers.py` 中的 `_DB_TOOL_MAP`（15 个 mapping_hint 的固定 DB 工具分配）
- Worker 工具分配改为动态：全部 DB 工具 + category=="needs_data" 时追加表格工具
- 章节分类（mapping_hint）仅用于 Worker Prompt 中的撰写策略提示，不决定工具集

#### 6.4 Prompt 无具体数据
- 所有 System/User Prompt 使用抽象占位符（`"投标人名称："、"XXXX 年 XX 月 XX 日"` 等格式说明）
- 无真实公司名、人名、金额、地址、日期

### 架构对比

| 维度 | 单体 Agent（旧） | Multi-Agent（新） |
|------|-----------------|-------------------|
| Agent 数量 | 1 个 | 1 Supervisor + N 个 Worker |
| 工具分配 | 10 个全给一个 Agent | Supervisor 4 个决策工具；Worker 6-9 个（全量 DB + 按需 OfficeCLI） |
| 决策方式 | Agent 自己做所有事 | Supervisor 决策分工，Worker 自主执行 |
| 并发 | 无 | ThreadPoolExecutor（max_workers=10） |
| Prompt 长度 | 200+ 行覆盖所有场景 | Supervisor ~40 行 + Worker ~30 行 |
| 故障隔离 | 单点崩溃全流程失败 | 单个 Worker 失败不影响其他章节 |
| 工具映射 | 无（单体用全部） → 硬编码 mapping_hint 映射 → **动态全量（最终方案）** | Worker 自主决定调用哪些 DB 工具 |

### 保留不变
- `scan_node`、`write_docx_node`、`BidFillerState`、`BidFillerAgent` 包装类
- `bid_filler_orchestrator_node` 适配器
- `bid_db_tools.py`、`office_cli_client.py`、`table_agent.py`、`rmb_formatter.py`
- `bid_generator.py`、`graph/builder.py`

## 10. 新增设计方案：标书打分 Agent (BidScorerAgent)

### 背景
系统已具备从招标文件中提取评分维度树 (`evaluation_metadata.score_tree`) 的能力，但尚无利用这些维度对我方标书进行自动打分的功能。

### 设计产出
- **[NEW] `docs/BID_SCORER_AGENT_DESIGN.md`** — 完整架构设计方案文档

### 架构选型
对比项目中已有的 4 种 Agent 架构（ReAct / Supervisor-Worker / Hub-and-Spoke / Linear Pipeline），最终选择 **LangGraph Map-Reduce Pipeline + 三轮共识投票**：
- 使用 LangGraph `Send()` API 实现 category 级别确定性并行 fan-out
- 不使用 ReAct Agent（打分任务确定性强，无需自主探索）
- 三轮 LLM 打分取中位数，确保结果可复现

### 核心设计
- **4 节点 StateGraph**：`load_node` → `score_category_node` (×N 并行) → `aggregate_node` → `report_node`
- **防幻觉五重护栏**：数据源锁定 → RAG 兜底 → 分值截断 → 三轮共识 → 数学校验
- **新增 2 张数据库表**：`bid_score_results`（打分会话）+ `bid_score_items`（逐项明细）
- **4 个 API 端点**：触发打分 / 历史查询 / 最新结果 / 逐项明细
