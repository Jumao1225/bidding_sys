## 8. BidFillerAgent 全自主标书撰写重构 —— Agent 成为标书撰写专家

### 8.1 架构变化

**修改前（6 节点）：**
```
scan → router(正则分流) → agent_fill(填槽) → self_check(规则自检) → llm_review(复核) → write_docx(写盘)
```
- 基于 19 条正则规则预扫描占位符
- `router_node` 将简单字段（白名单）直填、复杂字段提交 Agent
- Agent 角色是"槽位填充工"：拿到 DB 数据 → 返回映射表 → 后端统一写盘

**修改后（3 节点）：**
```
scan(写临时文件+提取上下文) → agent_fill(全自主撰写) → write_docx(读回输出)
```
- 去掉所有正则预扫描逻辑（`DETERMINISTIC_KEYS`、`is_complex_field`、`scan_detected_placeholders`、`router_node`、`self_check_node`、`should_run_agent`、`should_run_llm_review`、`llm_review_node`）
- Agent 角色从"槽位填充工"升级为"标书撰写专家"

### 8.2 Agent 的新行为

1. **自主阅读文档** `officecli_query_doc_structure` → 完整了解章节结构、空白位置
2. **查询数据库获取事实** `query_company_profile` / `query_financial_quotation` / `query_project_metadata` 等
3. **🤔 作为标书专家思考如何撰稿**：
   - 数据库返回"XX有限公司" → 撰写"投标人：XX有限公司（盖章）"
   - 数据库返回 967840.36 → 投标函大写栏写"玖拾陆万...元整"，小写栏写"967,840.36 元"
   - 数据库返回 90 → 工期写成"90 日历天"
   - 落款日期写成"2026 年 07 月 27 日"而非"2026-07-27"
4. **OfficeCLI 原位写盘** `officecli_batch_update` → 将撰写好的内容写入 Word

### 8.3 State 精简

删除字段：`detected_placeholders`、`fast_mapped_fields`、`unresolved_fields`、`agent_replacement_map`、`cleaned_map`、`final_replacement_map`、`requires_llm_review`

保留字段：`document_id`、`original_context`、`db_session`、`company_profile`、`original_docx`、`docx_temp_path`、`audit_items`、`audit_report`、`filled_docx_bytes`

### 8.4 调用方更新

- **[MODIFY] `app/api/endpoints/bid_generator.py`**：3 处调用 `process_filling_tasks` 移除 `scan_detected_placeholders` 预扫描，传入空列表 `detected_placeholders=[]`。
- `process_filling_tasks` 的 `detected_placeholders` 参数保留以兼容旧调用方，但 Agent 不再依赖此数据。

| 节点数 | 6 | 3 |
