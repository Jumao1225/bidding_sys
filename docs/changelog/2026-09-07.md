### 1. 修复 BOM 表格数量/单位列与操作列拖拽宽度显示

- **问题背景**：BOM 表格“操作”列固定使用 200px 最小宽度，实际仅展示常态操作按钮时仍保留较大空白；表头拖拽手柄以 8px 宽度、越过单元格边界的蓝色竖条显示，容易被误认为异常分隔线；“数量/单位”列按 180–190px 预留空间，单字单位场景下存在额外空白。
- **核心改动**：根据当前清单中每行实际展示的操作按钮数量动态计算“操作”列最小宽度；常态按钮集合最低约 140px，存在脱离、重置等条件按钮时自动增加宽度，避免按钮被压缩，并支持继续向右拖拽扩展。拖拽手柄调整为贴合单元格右边界的 6px 热区，默认透明，仅在悬停或拖拽时显示蓝色提示，并增加指针捕获、取消拖拽与窗口失焦清理。“数量/单位”列改为按数量输入框、单字单位输入框和实际间距计算最低宽度，单位为单字时可收窄至约 124px。所有表头文字统一居中显示。取消备注和操作列固定，改为根据所有列当前宽度实时计算 `scroll.x` 的整表横向滚动，并在表头下方增加与 Ant Design 表格同步的横向滚动条，让用户随时查看备注、操作及其他隐藏列。

### 14. 修复上传任务 ID 被误用为文档 ID导致历史恢复 404 和会话 403

- **问题背景**：上传接口返回后台任务 `task_id` 后，前端立即将其写入 `bidding_document_id`，导致分析结果恢复接口使用任务 ID 查询文档并返回 404，ChatPanel 随后使用同一错误 ID 查询会话并返回 403。
- **问题根因**：后台真正的 `Document.id` 在异步分析线程创建文档记录时才生成，上传阶段的 `task_id` 仅用于 SSE 订阅和临时原文件预览，不能作为文档权限校验 ID。
- **前端修改**：新增 `documentIdentity` 工具统一管理真实文档 ID及变更事件；任务提交阶段清理旧文档 ID但不保存 `task_id`；收到 agent 日志或最终 SSE 结果中的真实 `document_id` 后再同步 App、ChatPanel 和历史页面；历史恢复或会话列表遇到 403/404 时清理失效的本地文档 ID，避免重复请求。
- **测试验证**：前端 Vitest 全量 7 个测试文件、79 项通过；新增任务 ID生命周期和失效文档清理回归测试；目标文件 Oxlint 通过；Vite 生产构建通过；使用本机 Chromium 完成登录页浏览器冒烟测试且无控制台错误。全量 `tsc -b` 仍受仓库既有未使用变量和类型错误影响。

### 18. 修复原文件下载接口的 OpenAPI 重复 Operation ID 警告

- **问题背景**：应用生成 OpenAPI 文档时，原文件下载接口出现 `Duplicate Operation ID` 警告。
