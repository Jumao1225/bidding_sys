## 标书打分 Agent 全链路微调重算与报告全域联动刷新

针对用户反馈的交互微调重算后中间卡片（校验告警、TOP 3 改进建议、总体评价摘要）未联动更新问题，完成了后端服务层重算逻辑的全局闭环重构。

---

### 1. 微调重算全域报告联动刷新 (`rescore_category_with_instruction`)
- **发现的问题**：之前在对特定大类（如 `价格分`）执行微调重算时，仅更新了数据库中的 `bid_score_items` 和 `category_scores` / `total_score`，但旧的 `validation_warnings`（如 `#LOG_2 价格分得 0 分`）、`top_improvements`（`价格分 +30分` 建议）及 `summary` 依然保留的是初次 0 分时的旧文本。
- **重构解决方案**：在 [bid_scorer_service.py](file:///d:/Myproject/bidding_sys/backend/app/services/bid_scorer_service.py) 的 `rescore_category_with_instruction()` 中增加了**全域报告数据联动重算逻辑**：
  1. **告警实时剔除 (`validation_warnings`)**：自动重新校验各大类得分，若该大类已被微调重算为非 0 分，自动将其对应的 `0分告警` 从记录中清除。
  2. **改进建议重新排序 (`top_improvements`)**：重新计算全量评分项的扣分 Gap（`max_score - ai_score`），得分变为满分的评分项自动从 TOP 3 改进建议中被剔除，排名由真正存在扣分的项目替补填入。
  3. **总体评价摘要实时重构 (`summary`)**：根据最新各维度得分、总分与得分率重新合成包含评委主任微调注解的自然语言评价摘要。

### 2. 满分项评语与界面 UI 区分改造
- **后端 Prompt 增强**：在 `_build_scoring_prompt` 中约束 LLM 在给出满分时必须生成针对具体项目响应亮点的满分评语理由。
- **前端 UI 动态区分**：在 `BidScorerLab.tsx` 中，满分项标题动态渲染为绿色的 **`🎉 满分判定理由 / Full Score Justification`**，扣分项渲染为红色的 **`⚠️ 扣分原因分析 / Deduction Cause`**。

## 精确针对单一评分项 (`item_code`) 粒度微调与轻量提速

根据用户需求，将微调重算从“整大类级”升级为“**精细支持单一评分项级**”。

### 1. 单项精准过滤与 RAG 检索开销优化
- ** Schema 扩展 (`bid_scorer_schema.py`)**：在 `RescoreCategoryRequest` 中引入可选字段 `item_code: Optional[str]`。
- **精准过滤 (`bid_scorer_service.py`)**：在 `rescore_category_with_instruction()` 中，若指定了 `item_code`（例如只重算 `施工方案说明` 或 `ITEM_01`），后端仅过滤出该单一评分项进行 RAG 检索与 LLM 评估，不再重复检索其他无关项或全大类项目。
- **全域指标联动**：依然实时重算全局 `total_score`、`category_scores`、`validation_warnings`、`top_improvements` 及 `summary`，确保数据100%一致。

### 2. 前端单项按钮精确绑定 (`BidScorerLab.tsx` & `bidScorerApi.ts`)
- **扩展 `rescoreCategory()` API**：接收可选参数 `itemCode`。
- **卡片按钮精准传参**：在具体的评分细则卡片上点击“微调”时，仅把当前细项的 `item_code` 或 `title` 传入 Modal 弹窗；在顶部大类徽章上点击“微调”时，依然对整个大类执行批量微调。

## ⚡ 智能文档解析 Multi-Agent 编排长流程跳过标书起草 (writer_agent) 节点配置

为提升多 Agent 协作长流程的调试与测试效率，避免在全流程分析中因大模型生成耗时的标书起草 Word 草稿而长时间等待：

### 1. `bid_filler_agent.py` 引入 `SKIP_BID_FILLER` 跳过开关
- 在 [bid_filler_agent.py](file:///d:/Myproject/bidding_sys/backend/app/agents/bid_filler_agent.py#L732) 的 `bid_filler_orchestrator_node` 增加 `SKIP_BID_FILLER = True` 全局控制开关。
- **机制**：当开启 `SKIP_BID_FILLER = True` 时，`writer_agent` 节点被调用时会立刻向 Websocket / SSE 发送 `worker_start` 和 `worker_complete` 节点成功状态通知并直接返回，不再发起耗时的大模型起草调用。

## 🔄 数据库已持久化数据的前端自动加载与无缝回显

针对用户提出的“已入库数据前端展示时自动加载”需求，完善了前端控制台的数据自动检索与恢复机制：

### 1. 前端自动检测历史报告 (`BidScorerLab.tsx`)
- **机制**：新增对选定/上传文件 `uploadedDocId` 的 `useEffect` 状态侦听。当识别到选中的投标文件 ID 时，前端自动异步请求后端的 `GET /api/v1/bid-scorer/results/{document_id}/latest`。

- **状态通知**：增加 `⚡ 已自动从数据库加载该投标文件的历史打分报告与穿透明细！` 提示通知，避免用户因刷新页面或重进控制台而重复触发 AI 打分计算。
