### 1. 支持表内分组行占位并生成分组内层级序号
- **问题背景**：导出结果中的表内分组行没有占用序号，分组明细仍按根节点连续编号，无法形成分组行、组内明细和子项之间的层级关系。
- **核心改动**：按明确的表内分组路径维护顺序计数；大分组使用一级序号，组内直接明细使用二级序号，表内子分组行占用同级序号，其明细在该分组序号下继续追加层级，显式 BOM 子项继续沿用父项路径追加子序号。
- **分组继承**：父节点存在分组、子节点未重复携带分组字段时，子节点继承父节点上下文，避免同一分组被重复输出。
- **兼容处理**：没有表内分组时保持既有全局或表外分区内编号规则；不依赖具体项目名称、分组名称或固定分组数量。
- **前端与导出**：前端导出树、DOCX 和 XLSX 使用一致的层级序号；DOCX/XLSX 的分组行分别保留序号列与分组内容列，其他导出字段不变。
- **测试验证**：后端 BOM 导出单元测试与接口测试 `9 passed`；前端分组与导出树单测 `9 passed`；Python 语法检查和 `git diff --check` 通过。

### 2. 修复平铺清单分组上下文断开导致的错误一级序号
- **问题背景**：部分表格行在解析后没有携带 `part_name` 和 `group_path`，导出序号器将其识别为隐式新分组，导致原有大分组内的明细被编号为新的一级序号，后续分组序号也被错误顺延。
- **问题根因**：根项序号计算只读取当前行的分组字段，没有利用平铺清单的原始顺序继承跨行或跨页的表内分组上下文。
- **核心改动**：新增根项分组上下文补齐逻辑；当前项缺少分组字段时继承最近有效上下文，遇到新的显式大分组或表外分区时切换或清空上下文；所有分组名称、项目名称和数量均由输入数据提供，不包含项目专用硬编码。
- **后端修改**：`bom_export_service.py` 在 DOCX/XLSX 共用的导出行收集和层级序号计算前补齐根项上下文，确保断点明细继续落在原内部表内分组下。
- **前端修改**：`bomExporter.ts` 使用相同的上下文继承规则生成预览树和导出前层级序号，并统一路径去重逻辑。

### 8. 按原文表格边界隔离表外分区与表内分组

- **前端修改**：成本页面按主模式互斥展示分组筛选栏和行内归属标签；历史数据无模式字段时按“表外优先、表内兜底”兼容推断；父子树回溯增加来源表格边界校验。
- **数据库影响**：不新增数据库表或迁移；新字段写入工程元数据和成本分析 JSON 快照，实体报价表恢复数据时从工程元数据补回。

### 16. 修复 DeepSeek V4 结构化输出长度限制导致的 BOM JSON 截断

- **核心改动**：新增 `DEEPSEEK_MAX_OUTPUT_TOKENS` 配置，默认设置为 `200000`；新增 `DEEPSEEK_THINKING_ENABLED` 配置，默认关闭思考模式。DeepSeek 请求通过 `extra_body` 原样传递 `max_tokens` 和 `thinking`，避免 LangChain 将其改写为 DeepSeek 不兼容的 `max_completion_tokens`。
- **诊断增强**：LLM 客户端缓存指纹纳入生成参数；当响应 `finish_reason` 为 `length` 时记录模型及 token 用量，并抛出明确的输出截断错误。
- **兼容范围**：仅对模型名或地址包含 `deepseek` 的请求启用专用参数，其他 OpenAI 兼容模型保持原有请求行为；环境变量可覆盖默认值。
- **测试验证**：LLM、模型配置、工程清单分块、BOM 层级及导出相关测试 `97 passed`；另有 1 个既有 `cost_agent` 测试因 `rag_service` 测试依赖缺失在装饰阶段失败；Python 编译检查和 `git diff --check` 通过。

### 12. 恢复工程清单长度超限分块
- **问题背景**：模型结构化输出达到长度限制时，原流程会将整个失败分块丢弃，导致清单明细、父子节点和分区上下文一起缺失。
- **问题根因**：分块失败处理只记录异常并返回空结果，没有对失败表格按完整行进行二次拆分，也没有兼容重试库包装后的长度限制异常。
- **核心改动**：增加长度限制异常识别、表格 HTML/Markdown 定位和递归行级拆分；只重试当前失败分块，保留表格前置文字及表头。表内分组重试时重新计算各子块的分组状态，避免沿用过期状态。
- **结果合并**：重试结果按来源表格、原始编码、名称、规格、单位和数量生成去重键，保持原始顺序并合并补充字段，防止恢复过程生成重复项。
- **边界控制**：不可再拆分的单行分块不会无限重试；普通异常仍按失败处理，不改变原有降级行为；未新增数据库字段或写入固定项目数据。
